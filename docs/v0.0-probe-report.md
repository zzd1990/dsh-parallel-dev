## 二、三个必须修正设计的地方（探针的主要价值）

### 修正 1：可选依赖要用 `ctx.get()`，不能用 try/catch 包 `ctx.X`

`ctx` 是**受 `inject` 约束的代理**。访问一个没有 inject 的服务会**直接抛错**：

```
cannot get property "webServer" without inject
```

也就是说，`ctx.webServer` 这种写法在没 inject 时不是返回 `undefined`，而是抛异常——`try/catch` 只能兜住症状，兜不住设计问题（而且会让"忘记 inject"变成难查的静默降级）。

官方文档（cordis 教程第 3 章「可选依赖」）给了正确写法：

```js
// inject 用于硬性依赖；可选依赖不 inject，在使用处探测
const greeter = ctx.get('greeter')          // 没提供方时是 undefined
greeter?.greet('maybe') ?? 'no greeter'
```

**已据此修改插件**：`inject: ['tools']`（硬依赖），`webServer` 走 `ctx.get('webServer')?.register(...)`。

### 修正 2：拿不到 `session.cwd`

`exec.agent.session` 存在、能取到 `sessionId`，但 **`session.cwd` 是 `null`**。

v0.1 的 worktree 路径**不能依赖它**。下一步要从 `session.header` 或 `agent.options` 找真实来源。
（注意：`process.cwd()` 在 headless 下是启动目录 `/private/tmp`，不等于会话工作目录，也不能用。）

### 修正 3：服务名是 `subagents`（复数）

`ctx.get('subagent')` → `absent`；`ctx.get('subagents')` → `object`。设计文档里写错了，已改。

## 四、开发回路的两个硬约束（踩过才知道）

### 约束 A：插件放在 profile 树之外时，裸导入解析不到

`--patch` 用绝对路径能挂上**入口文件**，但 Node 解析该文件自己的 `import '@deepseek-ai/dsh-tools'` 时，是**按插件自身位置**向上找 `node_modules`——插件在 profile 树外就找不到。

实测报错：
```
failed to import
Cannot find package '@deepseek-ai/dsh-tools' imported from
  /Users/.../dsh-parallel-dev/src/host/index.js
```
（而且这条错误在启动阶段可能被吞掉——官方文档提醒过：模块解析失败走 logger，可能早于 console 导出器就绪。）

**采用的做法**：把包同步进 `~/.dsh/profiles/<profile>/node_modules/`（`dev-sync.sh`），裸导入就能沿目录树向上找到 `profiles/node_modules`。**这与团队最终的 `dsh plugin add` 安装方式一致，没有开发/生产差异。**

### 约束 B：不要碰用户正在用的 profile

开发用独立 profile `pdevdev`（从 headless 派生），通过 `--patch` 叠加层挂载。用户正在跑的 `web`（127.0.0.1:19387）完全不受影响。

## 五、环境变量有继承污染（要记住的坑）

headless 会话里读到的环境变量：

```
DSH_PROFILE=desktop                              ← 不是本会话的 profile
DSH_WEB_URL=http://127.0.0.1:19387               ← 用户正在跑的 GUI
DSH_SESSION_ID=session-78a07a9b-…                ← 不是本会话的 id（本会话是 session-9e72dd67-…）
DSH_PROFILE_DIR=/Users/…/profiles/desktop
```

这些是**从用户正在运行的桌面应用继承下来的**。

→ **插件不能盲信 `DSH_*` 环境变量**，真实信息要从 `ctx` / `exec` 取。这条直接写进 v0.1 的实现约定。
